# Shared captured-result views

18 October2026. Text-only adaptive content increment; TASKS is the active queue.

| Before | After | Why |
| --- | --- | --- |
| Native shell lacks the MCP JSON inspection entry | One shared bounded candidate selector/control group | The result content determines reading options, not its command name |
| Terminal head/tail excerpts independently offer views | Whole supplied preview owns inspection outside folded/error body | Do not mistake a visible excerpt for complete JSON or delimited data |
| Each wrapper composes its own reader choices | Shared group with precomputed CSV/resource candidates and no duplicate nested wrapper controls | Consistent placement and bounded work |
| JSON reader follows its input props | Explicit open snapshot, matching CSV/resources; stable owner outside body-format branches | New captured output must not replace the text a user deliberately opened |

No new permanent panel, menu or dashboard. Choices wrap in a compact accessible group. Existing original/raw/result owners stay intact. Candidate analysis is limited to256KiB and existing sealed wrapper parsers; JSON prefix is only a hint, and on-demand data validation still falls back to Original. Resource/CSV child readers consume candidate models rather than reparsing them. Empty groups occupy no space. Reader bodies are ephemeral; no grants/source/drafts are persisted.

**Motion verdict:** Frequent view choices remain immediate. Existing modal arrival/exit and keyboard/reduced-motion behavior are reused; no new layout/content animation or fake progress.

**Validation:**Both TypeScript projects/build;542unit tests/98files. Ten structured/resource browser journeys cover plain shell, wrapped shell and MCP complete-original access while preview is folded, one control group, nested Escape/focus, CSV fallback, safe links, Markdown and desktop/phone. Three actual Drishya/Skeletongraph Codex/Claude long-history/multi-file Workspace regressions pass. Final stable body-owner extraction rechecked with UI TS/build and all ten focused browser journeys. No claim of full binary/media selector implementation or full-artifact recovery. No native turn, schema/API/dependency/telemetry or hosted CI.
