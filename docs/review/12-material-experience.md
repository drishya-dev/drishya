## What this pass actually implements

- **Lift / Emit:** the bounded material backing expands from a measured visible file location or tool instrument to the action's allocated reading space. It carries the source/change/terminal/external material shape. This is an empty, translucent SVG shell: captured text already exists at its final DOM position, remains selectable, and never scales, types, or waits. The source/dock also receives one finite outline. Read keeps two distinct relationships: calling instrument and requested file. A file-reference fallback remains qualified; invisible origins do not invent a location.
- **Resolve:** the same action retains its identity and captured input while its recorded result becomes available. Outcome contours use actual pass/fail/unknown status. Pending source says that the excerpt has not arrived; pending edits can display the captured patch-input artifact, without claiming it was applied. No final-only output is streamed artificially.
- **Settle / Surface:** older material remains fully readable, with shallow margin grips; on wide reading columns neighbouring surfaces overlap only four outer pixels, inside the surrounding reading padding. Text and controls do not overlap. Prose remains unboxed with the owning agent rule. The existing source-to-prose association is recorded order, not an inferred explanation.
- **Content chooses composition:** material silhouettes identify source, patch, search, terminal, tests and external calls. Source gets a reading rail; patches use the material's width; multiline command input previews retain up to 1,200 captured characters with an explicit cutoff; MCP arguments align by captured field, with six fields and bounded values. Full readers retain their existing paging and provenance. No new generic transcript or duplicate hidden text.
- **Repository context:** the overview labels and outlines the focused or most recent referenced file in the composed working set on the actual geometry, retains its full path beneath, and links into the existing file evidence reader. When static import edges exist, only that file's actual incident edges are highlighted. Static imports and recorded locations keep their existing distinction. This is not an inferred runtime pipeline or a historical reconstruction of the whole repository. Dock instruments share their material silhouettes with the arriving action while keeping every observed tool name visible.
