## Design inputs

The isolated designer receives the concept and reads backend routes, shared contracts and installed `emil-design-eng` and `animate` skills. Its output lives in `apps/ui/src/fresh/`. The entry loads that application only for `?experience=fresh`; it does not load Classic's components or styles. Classic remains the normal entry until the builder accepts the new direction.

Developer jobs are the starting point: understand what a tool actually received and returned; read captured source and changes; navigate the selected repository; inspect separately consented current files and Git; find evidence across history; identify actual agents and tool inventories; submit a prompt with supported attachments to the selected native session; handle exact approvals and reported usage. Long recordings use bounded history and artifact APIs. Genuine native progress fills the initial wait without pretending to expose encrypted reasoning.

Each capability must distinguish captured evidence from present-day workspace data and local user notes. A graph import is a static relationship, recorded order is order, and nearby activity is not a causal explanation. Missing native roots/configuration/content remain actionable unavailable states. No fabricated usage, causal arrows, hidden reasoning, character typing or policy switching.

## Composition built from developer jobs

The new application has a narrow navigation rail, a workspace shelf, a central work stage and an optional evidence inspector. The session library opens actual captured recordings and supports local discovery/import. A compact relationship strip provides context without consuming the history viewport; repository exploration and current Git review have their own workspaces. Prose remains unboxed beneath captured actions. The composer is part of the stage's allocation rather than an overlay obscuring code.

The designer used backend routes/contracts and skills only, without reading the old frontend, prototypes or screenshots. `fresh/FreshApp.tsx`, `api.ts` and `fresh.css` are independent implementation files. `main.tsx` chooses the entry; `classic-entry.tsx` preserves the fallback's original static stylesheet order. The fresh route never loads Classic's CSS or components. No new runtime dependency or event-schema change was needed.

- **Understand captured work:** bounded 24-passage history, typed read/search/edit/shell/test/MCP/delegation compositions, original captured artifact readers, complete truncated-prose retrieval, lexical source colouring, explicit gaps and captured-outcome status. Card previews disclose their scope and open the complete paged reader; an excerpt is never represented as all captured content.
- **Navigate evidence:** recording-wide search opens the original observation, earlier/later bounded history, file-linked recorded operations, real agents and captured tools versus native runtime inventory. The map shows evidenced static imports; its spatial arrangement is not a claim of causality.
- **Read and review:** separately consented current files, 50-file current Git pages, bounded patch reading/find, browser-local exact-patch notes and reviewed marks, freshly revalidated preview/save handoffs. Local action questions support resolve/reopen and remain explicitly separate from agent evidence. Text notes are redacted before local persistence.
- **Connect to a native session:** supported prompts, file/image/folder references, pasted images, reported model/effort/settings, exact native approval responses, interrupt of Drishya's own run and reported usage. Workspace consent and a fresh idle-other-clients acknowledgement are required for each submitted turn. No UI switch fabricates full-access permission or mutates native policy. Actual native-account lifecycle acceptance remains outstanding.
- **Observation and replay:** explicit passive journal watching/sync is independent of viewport Follow. Upward main-history wheel navigation detaches Follow; local source/result wheel navigation does not. Optional sequence replay advances independently of reading. Backward seeking masks pending pages, completed artifact caches and later file activity; search observation anchors cannot override an explicit replay seek.

## Material and motion review

Charcoal surfaces, ivory primary text and restrained blue navigation accents form a new identity. Primary prose is 14 px, source is 12 px and interface text is 13 px; metadata is subordinate. The ordinary 1280×720 stage retains approximately 275–301 px of history reading height. Responsive checks also cover 1440×900, 390×844 and 844×390. Inspector/Git/source regions constrain overflow inside their allocations, with horizontal source scrolling accessible without reaching the bottom of an entire long patch.

| Before | After | Why |
|---|---|---|
| A static newly mounted action | A finite 240 ms transform from a visible matching file/tool origin when the scene identifies an actual arrival | Shows source and destination without creating captured text or delaying capture |
| Late preview allocation changes | The same real material scales from its previous dimensions at its current position | Prevents stale scroll coordinates from producing a separate second arrival |
| Pointer controls with no acknowledgement | Short press/hover feedback and bounded surface entry | Makes interaction legible without continuously animating the reading task |
| Keyboard/reduced-motion reading | Immediate presentation without decorative travel | Preserves reliable focus and avoids unwanted movement |

Motion verdict: acceptable for an opt-in connected draft; not a human smoothness or ten-minute certification. No character typing, number counting, fake scanning or duplicate captured material. Origins are measured and checked for visibility/occlusion; missing origins receive no invented relationship animation. WAAPI transforms are cancelled on interruption/unmount. Deliberate selection opens the inspector rather than recreating Classic's hover enlargement.

## Firsthand actual-session findings

The independent route was inspected against the builder's actual Drishya Codex recording (8,068 observations / 4,118 operations / eight agents) and Skeletongraph Claude recording (6,946 observations / 2,215 operations). Private imports and screenshots stay in ignored `.local/` storage. No native prompt was sent and no real recording is committed.

Actual-session review exposed two important allocation issues: offscreen previews initially requested too many artifacts, so preview retrieval now waits for near-viewport intersection; a long rootless Claude recording's graph endpoint can contain only the latest passage, so the paths-only view supplements it with files from the currently loaded history page. It does not invent a workspace root or static imports. Its captured-path inventory is bounded, not a complete repository index. Claude's missing canonical root correctly disables current-file/native prompting with an explicit explanation.

Final Codex reading also exposed narrow tall command cards after inspector allocation. Cards now require at least 240 px where space permits, wrap into fewer columns and retain long commands/patch previews in bounded local scroll regions. Derived titles are compact previews; complete evidence remains in the inspector. Earlier-page navigation positions the reader at the new page's beginning rather than preserving a misleading bottom scroll position. The final eight-browser-journey rerun passes after this allocation correction.
