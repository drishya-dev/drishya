## Adoption verdict

I would use Drishya as a local companion for understanding agent work, reviewing changes, comparing captured evidence and returning to a recording. I would not yet use it as my only daily Claude Code/Codex interface. The credible differentiator is the connection between actual source, actual edits, captured output and agent identity. The blockers are context loss between readers, incomplete repository navigation, weak review continuity, insufficiently visible live session ownership and unclosed real-native lifecycle acceptance.

The app has meaningful substance already: bounded historical readers, explicit captured/derived labels, current-disk separation, tests-after-change caveats, independent observation, privacy-before-store, virtualized history/explorer, current Git consent and exact-patch review marks. This is not a transcript reskin. However, the user's recurring job is “understand, verify, decide, continue.” Too many transitions currently terminate that job or make the user reconstruct context.

Qualitative assessment of this served synthetic Classic, not a release certification: historical trust strong; visual identity coherent; prose reading good; source navigation uneven; map utility weaker than its visual prominence; multi-agent focus partial; current Git promising but narrow; native primary-workspace readiness unverified. I would avoid numerical post-fix scores until the current build and real workflows are exercised.

## Core evidence and reading

1. **P1 F/S — Exact captured search results lead to an empty reader.** In the sample's Search “amount”, click `src/payments/charge.ts:8 if (!amount) throw new Error('amount required');`. Destination says “No source bytes or patch were captured…” and offers only a Search action. It discards the useful exact line the user just selected. `History.tsx` search links open `filePanel`; `lib/file-evidence.ts` recognizes reads and edit artifacts, not search matches. Add a true captured-search-match evidence choice, retain the selected hit and its line, and show discontinuous excerpt ranges honestly. Never fabricate a continuous whole file from search hits. Provide the original action and separate current-disk reading as alternatives.

2. **P1 F/S — Source → dependency navigation loses the original review location.** Review work → `src/checkout/guard.ts` → Import connections → `src/cart/types.ts` replaces the guard patch with an unavailable source state. There is no Back/Forward restoring guard/patch/layout/scroll. `FileHistory.tsx` keys readers by path; `ImportContext.tsx` overwrites app state; test links close file reading entirely. Introduce a bounded evidence-navigation stack containing recording, evidence mode, path, artifact/revision, range, selected action, scroll, layout and width. The source→change→check loop should return to the exact place without reopening menus.

3. **P1 S — Current disk selection is not cleared during session switching.** `state.ts:openRecording` resets `filePanel` but omits `currentFile`; `CurrentFileReader` mounts for the remaining path and new recording ID. Opening another session can therefore open the old path under the new root or show an irrelevant read error. Clear current-file state on recording changes; add a two-root session-switch regression. This is source evidence, not a firsthand native-session test.

4. **P2 F/S — Current-index links route into historical availability without explaining the destination.** `ImportContext` correctly labels “Current index · not historical execution,” but its historical-reader neighbor buttons always open historical `FileHistory`, even with an approved current workspace. A current dependency with no captured source becomes a dead end. Let the user choose “Captured work” versus “Read current file,” or make the actual destination scope/availability visible before navigation. In bundles, preserve the unavailable state and show available captured matches rather than pretending current disk exists.

5. **P2 S — Whole-file find is absent.** `SourceFind` searches only the loaded page; `ArtifactReader` loads 200 lines; current-file reading is similarly bounded. This is honestly labeled, but developers expecting Find cannot answer “where is this symbol elsewhere in this captured file?” without manually paging. Add a bounded server-side artifact search with total/range limits, result navigation and historical artifact identity. Keep page find for immediate filtering.

6. **P2 S — Diff reading lacks find, jump-to-hunk and range-copy parity.** `DiffReader` offers layout and 120-line pages, while source has find/go-to-line/copy range. A large patch requires scanning pages for the next relevant hunk. Add hunk navigation, path-specific before/after line references, find scoped to this patch and exact selected-patch copying. Do not invent a reconstructed source when only a patch exists.

7. **P2 S — File-action pagination does not preserve a single evidence selection outside comparison mode.** Choices are made from 24 loaded actions; retained selections are appended only when `compare` is true. Paging can replace the currently read single artifact with the new page's first choice. Retain a bounded selected evidence reference in single mode too, or make paging explicitly separate from changing evidence.

8. **P2 F/S — The useful verification trail starts below the reading fold.** At 1280×720, guard patch fills the modal and “Test runs after this change” barely begins at its bottom. A developer must discover the important result below while top controls occupy substantial vertical space. Keep a compact verification summary/link visible near the selected change, with full provenance/caveats below. Do not replace order with a coverage or safety badge.

9. **P2 S — Multiple recorded checks are reduced to a count plus latest link.** `VerificationPanel` shows “2 runs” but only `lastCheck` directly; earlier runs require the global review/history. Offer an expandable bounded list so the reviewer can inspect the transition from failing to passing within the same file context. Preserve the cross-agent and later-change qualifiers.

10. **P2 F/S — Generic shell previews obscure the relevant middle.** The sample's `git diff` preview uses first-three/last-three output lines and a fold button, hiding the changed hunk in between. `TerminalPreview` recognizes failures but not captured patch output. Render a clearly derived patch-shaped preview when exact captured output parses as a diff, with raw output always available. Do not classify arbitrary shell prose as a diff.

11. **P2 S — Evidence selectors are difficult to distinguish in repeated actions.** `EvidenceColumn` labels choices as operation title + artifact label, with no owner/time/short reference in the select. Repeated “Read foo” or “Edit foo” operations look the same. Include captured owner and timestamp/ordinal in choices, plus a concise selected-evidence identity near the source. Long identities should wrap or open full text.

12. **P2 S/G — One temporary source pin is insufficient for a sustained review.** `ReadingReference` allows one bounded ephemeral reference and clears it across mode/cutoff/session boundaries. This is a useful honest feature, but cannot hold a source invariant, a patch and a failure while making a decision. Add a small explicit local evidence shelf with exact references, unavailable/stale handling and privacy-conscious storage; do not persist large captured text by default.

## Native workspace and session lifecycle

13. **P1 A — Actual native primary-workspace acceptance remains open.** Review 48 explicitly says account turns/platform/physical acceptance is unverified. Before claiming sole-workspace readiness, exercise both real harnesses: prompt/follow-up, approvals/declines, interrupt, attach text/image/folder, native model/effort, compaction, disconnect, daemon restart, missing journal, second-client activity and session switching. Mock transport tests prove protocol handling under those mocks, not current account/version compatibility.

14. **P1 S/G — The prompt target is visually hidden.** `PromptComposer` puts root and controller state in `.composer-target.sr-only`; Classic header says Local workspace/title, while `agentName` can be a model shared by many sessions. Before sending, I need a concise always-visible harness/session/worktree/root identity and turn ownership. Show the exact selected target beside the composer or its native settings, with a readable full identity disclosure. A title is not a unique worktree identity.

15. **P1 G/A — Other-client ownership relies on user acknowledgement.** The controller requires `exclusive===true`; UI says “This session is idle in other clients.” Correctly do not weaken this safeguard. But a checkbox cannot detect a second client starting immediately afterward. Make ownership explicit (“This turn controlled here,” observer remains independent), report supported native conflicts and fail safely. Validate the real collision lifecycle. Never claim exclusive ownership is enforced across arbitrary clients without evidence.

16. **P2 S — Unsent drafts and attachments vanish on session switch.** Provider/composer are keyed by recording ID and use local state. This prevents accidental cross-session sending, but tabbing between work loses drafting effort. Preserve bounded drafts per session in memory, clearly label target, and offer deliberate clearing. If durable drafts are later added, redact before local persistence and disclose storage; images require their own privacy treatment.

17. **P2 S/G — The composer blocks drafting during an active turn.** Textarea is disabled for connecting/running/approval. Users cannot prepare a follow-up while reading progress. Permit draft editing with Send disabled, or add an explicitly manual queued draft that never submits automatically. Keep approval/stop controls available and keep acknowledgement tied to the eventual send.

18. **P2 S — Prompt length validation uses incompatible units.** Textarea `maxLength=65_536` counts characters; controller caps UTF-8 bytes at 64 KiB. A permitted CJK/emoji prompt can fail at send. Show byte-based remaining capacity and validate before submission; preserve draft on rejection. This is not a reason to raise backend bounds.

19. **P2 S/G — Attachment review is name/thumbnail only.** `promptFiles` supports 32 files with combined limits; composer previews image thumbnails but text only names. Folder selections can be all-or-nothing rejected on one unsupported/oversize file. Add a preparation review showing path, size, type, text redaction result and per-file exclusions/removal before submission. Maintain exact limits, no silent truncation and explicit pixel privacy.

20. **P2 S/G — Supported slash commands are not sufficiently discoverable.** Native settings gather commands, but composer offers no command picker/compatibility explanation; Codex rejects everything except exact `/compact`. Show only supported controller commands with capability scope and native-client handoff for unsupported commands. Do not promise arbitrary CLI parity.

21. **P2 S/G — Setup and recovery actions remain terminal detours.** Missing CLI gets install/login instructions; settings probe errors mention timeout/sign-in. Add a concise readiness panel showing discovered executable/version, account-access status when actually reported, native session resumability, workspace grant and supported features. Offer copyable next steps and a retry; never store credentials or infer sign-in from installation.

22. **P2 S/G — Usage is truthful but operationally thin.** UsagePeek correctly distinguishes last model request/connected turn, cumulative thread tokens and context capacity. The parent is fixing clipping. After containment, show freshness/time/scope beside values and a context ratio only when actual native occupancy is available. Historical accounting, subscription limits and estimated price must remain separately labeled or unavailable. Do not turn cumulative usage into context occupancy.

23. **P2 G — Starting work still requires a preexisting native journal.** Home asks users to start a native harness and refresh; controller resumes a selected known journal. A primary workspace needs an explicitly scoped new-session launch flow or a clear “continue existing native work” product boundary. Build launch only through supported harness protocols with root/policy consent and captured identity; Drishya must not fabricate journals.

## Review, Git and return-to-work

24. **P1 S — Git snapshot's race check misses content-only edits.** `git-review.ts` collects status/HEAD before and after, but a file that remains ` M` can change contents during the staged/working patch reads while status and HEAD remain equal. The snapshot can combine moments without raising its “changed during inspection” error. Verify per-file content/index identity before/after, use an adequately bounded consistency strategy, or explicitly qualify non-atomic sampling. Existing tests check changes between snapshots, not this mid-snapshot content race.

25. **P2 S — Git review progress is per recording/browser, not a durable repository review.** Key is `drishya-git-review-v1:${id}`; another recording of the same worktree gets no progress; another browser loses it. Exact-content invalidation is excellent. Extend identity to repository/worktree plus displayed patch fingerprint, retaining deliberate local ownership and a migration/export story. Do not attribute current edits to the agent.

26. **P2 S — Stale review notes disappear from the accessible UI.** On fingerprint mismatch, textarea shows empty and updates replace the note; the list says Changed, but gives no old-note comparison/recovery. Retain previous notes as clearly stale context so the user can re-evaluate instead of losing reasoning. Reviewed must still reset for changed content.

27. **P2 S — Git file bounds can hide all later small patches behind one large patch.** `snapshot` breaks when a patch exceeds the remaining 1 MiB budget, so subsequent smaller files are never sampled. UI groups omissions as protected/content/50-file limit. Show specific omission reason per path and permit bounded explicit file retrieval; skip an oversized path rather than silently ending useful review. Avoid unbounded reads.

28. **P2 S/G — Git patch reader lacks developer diff affordances.** `GitReview` passes the staged+working patch to generic `CodeView`, with no hunk jumping, selectable staged/working scope, wrap/find or before/after coordinates. Reuse bounded diff reading rather than adding a second thinner review engine. Binary, untracked, rename and submodule states need distinct reading outcomes.

29. **P2 G — Historical work has no durable review queue or unresolved-decision state.** Since-mark and Review work enumerate captured outcomes; source pin is temporary; Git notes concern only current patches. The sample explicitly leaves a free-order payment risk for a decision, yet there is no explicit user-maintained place to retain it. Add local reviewer questions/notes/pins anchored to captured evidence, with owner/status and return digest. A heuristic “agent left a risk” summary must never masquerade as captured intent.

30. **P2 S/G — Review result limits have no focused continuation.** EvidenceReview says “Showing N of M; remaining evidence stays in history”; search caps 50; changed file list may be partial. Large sessions need continuation paging/filtering directly by outcome/file/owner, not instructions to reconstruct a query. Keep global counts and bounded result windows separate.

31. **P2 G — Handoff covers current reviewed Git, not historical reasoning/evidence.** Existing handoff is a good privacy-previewed local artifact. Add a curated historical packet containing exact selected source/patch/result references, unavailable reasons, recorded checks and separate reviewer notes. Exclude private full transcripts by default; show payload before saving/sharing.

## Repository and agents

32. **P2 F/S — Map makes files visually present without reliably answering dependency questions at rest.** The default 14-file spatial view has thin crossing edges and tiny labels; direction/scope is in the optional Import paths drawer. At narrow width right endpoints/labels are clipped. Make the selected-file neighborhood the actionable focus, label import/importer direction in a bounded DOM list, and retain world orientation. Keep 3D/orbit as the builder-requested option, but do not require orbiting to answer “who imports this?”

33. **P2 S — Fit is an orientation reset rather than a measured fit to current endpoints.** Full-map Fit sets yaw/pitch and `{x:0,y:0,k:1}`. The screenshot shows clipped narrow endpoints; a transform reset cannot guarantee labels fit. Fit projected node+label bounds into actual unobscured viewport and reserve the controls/readers; neighborhood fit already has useful machinery to reuse.

34. **P2 S/G — Repository exploration still lacks outline/definition navigation.** Imports are useful but insufficient for tracing code within a file. CODEBASE/STATUS retain semantic indexing as staged work. Add supported-language outlines and definition/reference navigation with resolvable/unresolved labels and explicit current-vs-historical scope. Avoid implying broad language support from filename icons.

35. **P2 S/G — Diagnostic locations need first-class navigation.** Failure preview identifies assertions; captured test/terminal paths are not a general structured diagnostic-to-exact-artifact flow. Add bounded parsing for actual captured file:line diagnostics, with target availability and current-disk alternative. Temporal proximity must not select a fictitious matching revision.

36. **P2 F/S — Agent focus does not lead to that agent's useful work.** Clicking Claude at the final Codex response retains the current viewport, dims unrelated material, and adds clear-focus controls. Context retention is correct, but users must find the focused work manually. Offer previous/next focused action/turn and optional isolate view; show focus count/scope. Parent-child disclosure is being fixed by the parent and is not an outstanding duplicate request here.

37. **P2 S — Model/harness identity can collide.** `identity.ts` uses the same hue for all root agents of a harness and often uses a model as name. Two independent Codex sessions can be indistinguishable. Add stable short captured session/worktree identifiers and optional user aliases kept separate from captured labels. Do not invent family links from simultaneous activity.

38. **P2 S — Agent and tool focus cannot compose.** `setFilter` replaces one filter; selecting Test after an agent loses owner focus. Offer explicit compound filters for agent + kind/server/path with removable visible chips, plus a clear-all action. Bound worker requests and preserve surrounding context by default.

39. **P2 S/G — Explorer is usable but lacks normal tree keyboard parity and working-state context.** Up/Down/Home/End work; Left collapse/parent and Right expand/child are absent; all rendered buttons remain tab stops. Add roving tabindex and normal tree semantics. Separately expose evidence-backed changed/read/error states without confusing extension color with work status. Current Git status must remain explicitly current.

40. **P2 S/G — There is no normal external-editor handoff.** Historical/current readers require the user to leave manually for a definition, richer document or larger editor task. Offer copy path+line and an explicit configured editor handoff; historical artifacts need an exported temporary reference or clearly marked current-file handoff rather than silently opening today's code as the recorded version.

## Error, recovery and performance

44. **P2 S — Graph failures can be silent.** Viewer initial graph load catches and discards errors; folder explorer reports its load errors, but neither has a consistent explicit graph retry state. Keep last valid map when appropriate, show “map unavailable/stale” separate from capture health, and offer retry without resetting history selection.

45. **P2 S — Verification load errors lack Retry.** Artifact readers/FileHistory/EvidenceReview have retry paths; VerificationPanel renders an error only. Add retry in place and preserve chosen change. A checks service failure should not force a full recording reload.

46. **P2 S/G — Home recovery/storage management remains CLI-heavy.** Missing nonstandard journals and over-budget storage point to terminal import/forget commands. Offer read-only discovery diagnostics, explicit import selection and a concrete storage inventory/export-before-removal flow, retaining required destructive confirmation. Do not auto-delete data or silently scan arbitrary folders.

47. **P1 A — Performance evidence is credible but bounded.** Reference-machine long-session gates and virtualization are documented; physical low-resource/lower-core and platform gates remain. This review ran no benchmark/soak. Measure the current build with large real redacted sessions, many live agents, large diffs and current Git sampling; include input/scroll latency, DOM bounds, memory, dropped frames and passive-capture overhead. A synthetic 14-file sample cannot establish those workloads.

48. **P2 S — Current Git is sequential and can feel hung on many files.** It runs staged and working `git diff` for each of up to 50 files, each with a 10-second timeout; UI has only “Inspecting…” until complete. Add bounded total deadline/cancellation or progress, and one-file lazy reads. Preserve no-shell/no-filter/no-network safeguards. This is a scaling risk from code, not a measured stall.

49. **P2 A — Reconnect and native/capture state need an operator-level acceptance journey.** The UI has reconnect labels, controller phases, history retry and capture health. Validate that a user can distinguish agent stopped, controller failed, capture missing, daemon disconnected and last content retained. Recovery should state whether a prompt was accepted before offering retry, preventing duplicate turns. No duplicate native send was observed in this review.

## Suggested delivery sequence

1. Finish concrete defects already being handled: Usage containment, nested Agents/Subagents; then mobile duplicate icons, current-file session reset and exact captured search destinations. Recheck the served current build and keep the report's old-build observations distinct.
2. Implement a bounded shared evidence location/history, with selected search line and source→patch→check→Back preservation. Improve full-reading typography and diff navigation within that work.
3. Close real native lifecycle acceptance while making composer target, worktree, policy freshness and turn ownership visible. Drafting, command capability, byte validation and attachment review belong here.
4. Add durable user-owned historical review questions/queue and useful return digest; extend current Git consistency, note continuity and bounded handoff. Keep captured prose, current code and reviewer interpretation visibly separate.
5. Make repository/agent navigation answer concrete questions: selected import neighborhood, typed diagnostics, supported outline/definition, compound focus and editor handoff. Keep the spatial world as product identity while the plain list remains a reliable navigation instrument.
6. Run sustained real reading and accessibility/platform/resource acceptance on the resulting integrated Classic. Avoid another theme prototype as a substitute for these jobs.

## Acceptance scenarios that would change my verdict

- Return after a day: see new failures/edits/checks and unresolved reviewer questions, open a selected patch, inspect its exact source/check, return to the same reading point, and continue the correct native session.
- Two similar same-harness sessions in different worktrees: select one, read current code, switch, draft independently, attach safely, approve one exact request, interrupt only the owned turn, recover after restart without target ambiguity.
- Large real review: find across a captured artifact, inspect distant diff hunks, retain evidence references, follow captured diagnostics, distinguish current Git drift and save a curated handoff.
- Ten-minute comprehension: maintain readable prose/source, predictable nested scrolling, keyboard/touch alternatives to hover, quiet background geometry and reliable Follow behavior while capture continues.

If those are dependable, Drishya can become a primary agent workspace for the scope it actually supports. Until then I would keep the native client and editor beside it, using Drishya's evidence view as the part that makes agent work understandable.
