# Studio working experience and complete preview reading

11 October 2026 · Developer feedback continuation

Studio is a second working composition of the actual product, selected under Settings → Workspace design. Classic preserves the earlier design. Studio is the default; `?experience=classic` and `?experience=studio` choose an initial design without changing the recording. Both share capture, evidence provenance, readers, navigation, consent and native control. This is integrated React UI, not another standalone HTML prototype.

Studio has its own session header, instrument dock and two-line action identity, with a coordinated reading layout, compact inline composer, folder rail, dialog materials, typography and narrow-screen layout. The session title is centered; only actual multiple agents get an agent row. Native instruments and MCP connections remain distinct genuine motion origins. Prose remains unboxed. Neutral action materials use semantic icons/syntax and error contours. The dark Jet palette uses a cool black base, pale text, aqua outcomes, amber edits, blue source and purple connections; other palette preferences remain selectable. Classic's texture remains available in Classic.

The redesign reuses the measured, interruptible single-real-DOM material engine, rather than inventing a second source of captured text. New compositions supply their actual origin/allocation geometry. Reduced motion and low-resource fallbacks remain shared. No claim is made that every backend or motion primitive was rewritten.

## Complete captured content

The builder clarified that removing a spurious scrollbar must not remove content. Edit previews now mount all captured hunk lines up to 600 lines; larger patches have explicit 120-line pages, starting near the first change. Source previews fetch 200-line pages with Previous/Next controls. A long preview scrolls inside its material. Nothing is represented solely by an unreachable “N more lines” count in these two compositions. Full readers and provenance distinctions remain available. Paging is a resource bound, not evidence loss.

## Hover correction

The later Studio resting-height rule accidentally capped a focused material, producing horizontal-only enlargement. Resting caps now exclude focused materials. Hover allocates both dimensions using the current measured rectangle, the actual body overflow and available viewport bounds. Short cards have modest vertical enlargement; long cards grow to the available reading space and retain scrolling. One 360 ms transform carries position and both dimensions together; return is interruptible at 320 ms. The existing measured-slot, cursor-boundary, scroll-carry and edge-veil behavior remains. No captured text is duplicated.
