# 28 — One arrival, a quieter frame and a progressive dot map

7 October 2026. This is the latest builder correction, superseding conflicting presentation details in reviews 24–27. Work belongs in the integrated application, not another HTML study. Data contracts, independent observation, redaction and native controller permissions are unchanged.

## Direction and implementation

An arriving action is **one real DOM material**. The previous implementation also flew an empty SVG backing and an instrument/file silhouette on separate timings. Those overlapping representations made a coordinated surface transform look like travel followed by a disconnected zoom. They are removed. `Origins` now uses the measured file reference/map point or tool instrument to drive one `moveMaterial` translation and scale, approximately 1.4–1.65 seconds, with a shared easing curve and deadline. Real geometry changes retarget from the last visible rectangle. Existing material reflow remains finite and interruptible. A small origin/thread cue identifies a relationship; it is not another arriving box or copy of its content. Late excerpt availability receives an edge cue at its existing home. Reading/reduced motion suppress motion immediately; automatic pacing holds do not cancel an arrival. Content stays mounted whole, selectable and captured.

The frame has a centred session title and recorded-agent switches, with a translucent fading header treatment rather than another opaque panel. This uses alpha/gradient colour, not a blur or extra graphics dependency. Black and the subtle static charcoal lining remain. Materials have stronger cyan/source, amber/change, lilac/external and green/red outcome boundaries; syntax keeps distinct keyword/string/function/number/type/property/comment colours. Agent identity is captured; a synthetic model placeholder is not used as the agent name. The global synthetic demo label remains visible.

Cards are denser: 28 px minimum headers, 11 px preview code, approximately 210–480 px content-dependent allocations and a 245 px preview ceiling. Expanding still opens full reading space, with real overflow and adjustable readers. The ceiling is not a universal height requirement: a short result needs only its content. A compact result that fits can remain in follow; a large result still invokes the independent readability hold. The acceptance criterion is a visible request and reachable captured output, not a mandatory hold after every result.

The ordinary native composer sits at the bottom, with measured history clearance, compact padding and an always-visible textarea. Workspace consent, native availability, idle-other-clients acknowledgement, Enter/Shift+Enter/IME handling and exact one-time approval remain. Prompts opens captured chapters and edit/failure navigation in one popup. Watch-live and return-to-latest are at the bottom right. Export is in the workspace overflow menu. Motion, map visibility, resource mode and optional sequence replay are in Settings. The primary header no longer has Briefing, and operation detail no longer has Explain. Existing generated-evidence APIs and stored features are retained; do not silently change other builders' backend work.

The left tree keeps the selected session's files, extension/folder icons, search, minimize, bounded pages and consented file reading. Duplicate Explorer/Current workspace index/File relationships/Repository map sections are removed. The right dock keeps actual observed names and any separately qualified connected-runtime inventory. The redundant recording caption is a tooltip; observed use still must not imply availability. Tool hover uses quiet emphasis, with a neutral keyboard focus indicator instead of the blue boundary. Calendar labels show today's time, Yesterday or a date; hovering shows the full timestamp. Recorded-order qualification remains in the connector's accessible title instead of beside every agent label.

## Map: density, not directory drill-down

The graph is one continuous field of small white circular nodes and actual import connections. Larger dots represent derived spatial density groups. A folder explorer is separate; directory hierarchy does not decide graph membership. Root configuration files such as `.gitignore` remain individual nodes at their real positions.

`map-detail.ts` caches a nested 4/8/16-bin spatial pyramid for a graph object. From zoom 1 to 8, adjacent levels blend with smoothstep: coarse groups fade back while child nodes emerge from the parent centroid and interpolate to their own coordinates. The final level is the original graph. This is a navigation transformation, never evidence of execution, dependency inference or agent causality. Group labels use a shared path prefix where available, otherwise Mixed files. Imported edges aggregate only original edges; groups cannot be passed off as files.

`MapCanvas` animates camera changes for 360 ms, retargets wheel destinations and cancels for drag, motion preferences or leaving exploration. Zoom buttons preserve the view centre; cluster clicks and search centre the chosen region. Camera commits paint immediately in a layout effect—another scheduled paint RAF could be cancelled by the next camera frame. At rest there is no animation loop. Nodes retain modest screen-space sizing. Labels are DOM text, culled before ranking, collision-rejected and capped at 48; imports have a 600-edge visible paint budget. Exact file origins are offered only when an individual node has effectively reached its visible position. Occluded map nodes fall back to another real file reference/instrument rather than claiming a hidden origin. Current `.local` caches remain excluded; captured historical evidence is not discarded.

These changes improve the existing bounded renderer; they do not certify arbitrary graph sizes or replace future indexer/renderer performance gates. Tiny/synthetic and reference-machine checks are not low-core/platform certification.

## Research used

- [Sigma's appearance documentation](https://www.sigmajs.org/docs/advanced/customization/) describes configurable round nodes/edges, neighbourhood emphasis and label presentation. The transferable principle is to distinguish graph geometry, focused context and readable labels. Drishya keeps text in the DOM rather than adopting its canvas-label implementation.
- [Sigma v4 size concepts](https://v4.sigmajs.org/concepts/sizes/) discusses the relationship between zoom and node/edge sizing. That site is explicitly **alpha v4**; it is a research reference, not a new production dependency or a claim that our current renderer is Sigma. We use restrained screen-space sizing and gradual detail instead of magnifying huge nodes.
- `docs/prototype/index.html` remains the builder's material/motion and navigable-dot-map reference. Its illustrative graph is not proof of measured large-repository support. Actual captured content, exact locations and bounded budgets win over a promotional effect.

## Later: attachments in the same composer

The builder explicitly wants file/folder additions **later**, alongside ordinary text prompting. Keep one composer, reserve an accessory row that expands only when used, and use small removable reference chips. File selection must be rooted in the already consented workspace; folder context needs an explicit bounded selection/preview, not an automatic recursive upload. Current-disk context and historical excerpts must remain distinguished. Do not invent captured content, add a fake functional upload button, silently transmit whole files, or imply all harnesses support the same attachments. Design and validate the native protocol/API seam before implementing attachments; any evidence schema change still needs both builders' agreement. No attachment capability is claimed in this pass.
