## Builder corrections and delivered behavior

- **Actual spatial points and edges:** stable file-specific Z coordinates, yaw and pitch rotation, perspective, GPU point/line rendering and depth testing. This is a WebGL spatial view, not the previous 2D sinusoidal depth effect. File depth is derived presentation layout, never dependency strength or execution evidence. Only actual indexed import edges are drawn. The existing density pyramid groups real file membership and averages member depth; zoom blends to individual files. DOM labels, picking and file-arrival anchors use the exact same camera projection as the GPU. Text never enters WebGL.
- **Camera:** drag orbits around both axes; Shift drag or middle-button drag pans; wheel/buttons zoom; Fit resets. Background rotation is on by default for new preferences, bounded to 15 fps and resumes 12 seconds after manual camera movement. Existing explicit choices persist. Hidden tabs, reduced motion, low resource mode, no nodes and more than 1,500 displayed items stop automatic rotation. Static/flat options remain in Settings. WebGL failure/context loss falls back to the flat canvas; renderer resources are disposed when disabled. Device-wide low-resource performance remains a release measurement, not a claim from the browser test.
- **Background:** nodes and lines share steady white opacity; neither dims because a tool/file was hovered. No background file names. Labels appear in exploration and avoid navigation chrome. The old reading-column graph mask is removed. Header/composer edge veils remain, as does the real DOM reading space.
- **Rails:** left content space grows by roughly 12–16 px and right tools by roughly 14–22 px, with reduced widths at intermediate screens and overlays on narrow screens. Work stays centred independently of folder visibility. Responsive checks cover desktop, ultrawide, portrait and short landscape windows; no finite matrix can certify every device.
- **Shared action cards:** read, write, edit, search, shell, test, MCP, web, other, spawn and plan use one non-shrinking header. A long title ellipsizes within its actual allocation; its full value remains in the tooltip/reader. Status, type icon and Expand remain in bounds. MCP server names are separately bounded. Result tables wrap into their allotted width instead of forcing a 480 px table into small cards. Long plan tokens and structured argument/result fields wrap. These rules apply at rest, hover and expansion without changing the existing same-material animation or live/replay/scroll behavior.

## Attachments: implemented transport and limits

The compact composer + opens file/image and folder-content pickers. Drag/drop and clipboard screenshot paste use the same conversion path. Removable chips and local image thumbnails remain bounded; they clear only after accepted submission and stay on failure. Drafts are memory-only, never localStorage or Drishya's store. Folder selection preserves relative paths. It uploads selected contents, not a fabricated arbitrary absolute-path capability.

Supported: UTF-8 code/text and PNG/JPEG/WebP/GIF images. Limits: 32 files, 512 KiB text combined, 4 MiB per image, 6 MiB overall; the authenticated prompt route alone permits a 9 MiB JSON body. Binary documents, oversized inputs, invalid base64, mismatched image signatures, traversal and protected names fail explicitly. Large folders require a smaller selection; nothing is silently omitted. PDFs/archive/audio/video and lazy workspace-folder references are not advertised as supported.

The daemon validates before native launch and redacts complete text/names before sending. Text becomes explicit attached-file content; Claude receives native stream-json image blocks and Codex receives inline data-URI image inputs. No shell interpolation, new native settings, arbitrary terminal attachment, temporary image files or fabricated journal events. Controller status contains safe names/types only, never image bytes. Private payloads release after send/termination. Images cannot be scrubbed by the text redactor: the composer tells the user to review images; explicitly supplied pixels go directly to the native harness, whose own retention and permissions still apply. Passive ingestion continues sanitizing the harness journal independently.

Protocol sources: [Claude streaming image inputs](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode), [Codex app-server inputs](https://learn.chatgpt.com/docs/app-server), [OpenAI's inline-image transport test](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/suite/v2/turn_start.rs). The local tests verify actual serialized transport frames with synthetic native processes. They do not certify a real image model response on every native version or lift the existing Claude account restriction.
