## Reading focus and later multi-agent work

The hover zoom proposal is worth a separate interaction prototype, but automatic whole-card relocation is not shipped as the default: moving a card out from under the pointer causes enter/leave oscillation, a centred overlay obscures neighbouring hit targets, and fast switching competes with actual origin/reflow motion. Keep bounded previews, whole selectable content and explicit Expand/source readers now. These support mouse, keyboard and touch without making pointer movement detach live follow. Preview wrapping, long MCP labels, terminal input, JSON and code-line overflow are checked independently of the full reader. Very long evidence still requires a bounded reader; hiding its scroll or pretending all lines fit would discard access.

Later prototype an **opt-in** hover reading focus with a stable resting hit region, approximately 250 ms dwell, one active focus at a time, interruptible transfer between cards and return on leave/Escape. Use real evidence without animation copies; measure final geometry, do not mix two unrelated animations or enlarge captured characters as decoration. Pointer movement alone must preserve capture/follow. Rapid A→B→A, crossing the focused surface, long output arriving during focus, selection/copy, code ranges, keyboard/touch, reduced motion, map-off, narrow viewport, reader resize and virtualized unmount are required checks before enabling it. No hover zoom is claimed implemented in this pass.

Use captured IDs, names, parentage, ownership and native lifecycle; do not invent agent names/work or launch agents just to populate the UI. Test overlapping tools, child completion, delayed/interleaved output, MCP inventory changes, unknown agent parentage, sparse/large maps, explorer consent/current-versus-historical reading, source occlusion, mixed success/errors, reconnect/gaps, rapid selection and ten-minute reading.
