# Keyboard workspace navigation

13 October 2026. Review 50 item 42. Uses installed `emil-design-eng` guidance: frequent keyboard commands are immediate, with no decorative entrance delay.

| Before | After | Why |
| --- | --- | --- |
| Practical workspace actions are spread among the header, dock and menus | Ctrl/⌘ K action/file/session picker with a visible evidence-desk entry | Reach common developer jobs without hunting through chrome |
| Escape in a modal can also close the reader underneath | Global shortcuts defer to the open native dialog | Close one layer, preserve the reading context |
| Opening an indexed file could imply historical content | Destination labels current indexed disk versus captured file work | Keep ordinary disk consent and evidence scope intact |

Commands include captured search, map, latest activity, settings, recorded review/questions, separately approved current Git and local session selection. File/session matches are limited to forty displayed destinations with refinement; files come from the loaded graph, sessions from local recording metadata. No command execution, harness launch, policy mutation, fuzzy semantic claim or external-editor scheme is introduced. Native read/consent/permission components own their actions. Input/arrow/Enter/Escape semantics use a labeled combobox/listbox; keyboard reveal/selection is immediate. The palette does not open over a blocking native dialog. Root theme focus remains visible and neutral.

Browser acceptance opens exact captured file work by keyboard, preserves the Inspector on palette/settings Escape and follows keyboard selection. Existing menu/focus/reading regressions are rechecked. No new motion, capture/schema/dependency or telemetry changes; final cumulative checks are recorded in STATUS. Home already has workspace/session filters; this picker currently targets an open workspace rather than starting or importing an unknown native journal.
