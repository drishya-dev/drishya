# Native progress, exposed reasoning and optional depth map

Builder direction, 8 October 2026: evaluate an efficient rotating 3D repository background; remove the blank period after sending while the agent has not emitted text/tools; integrate exposed thinking correctly for Claude Code and Codex. File/folder attachments and a complete settings/permissions round trip are subsequent product work.

## Native turn lifecycle

The composer previously hid controller state and polled every 1.8 seconds. It now shows an immediate **Sending prompt** receipt in the work column, replaces it with the accepted native connection state, and wakes active polling at 500 ms. Idle polling remains 1.8 seconds; hidden tabs do not request status. Older in-flight status responses cannot overwrite newer accepted submission state, and switching recordings discards stale responses.

Accepted prompts are redacted by the daemon before returning a bounded **Submitted here** receipt. This is explicit controller input, not a fabricated journal event. Connecting, waiting, thinking, responding, tool work and approval states are presented unboxed in the history world. `Thinking` is used only after a genuine native reasoning/thinking event; generic silence is **Waiting for the agent**, never invented reasoning. The native CLI may still need time to initialize/sign in/load context; this work removes silent UI latency, not actual model/startup latency.

Claude launches its structured resumed-session transport with `--include-partial-messages`. Native thinking/text block starts and stops provide phase and complete exposed material. Main-agent content is distinguished from subagent forwarding. Codex consumes app-server item starts, response deltas, reasoning summary/raw-text deltas when provided, and completed items; thread/turn scope is checked. Encrypted reasoning is never decoded. A completed item supersedes its delta accumulation.

Unfinished arbitrary token fragments remain private in bounded in-memory buffers: 16 blocks × at most 65,536 characters. A credential split across deltas must not briefly leak on screen. Complete blocks are redacted before returning their latest preview; oversized blocks are omitted whole. Buffers clear when a turn ends. Only the latest live block is displayed, separately labelled **Live from harness**; normal journal capture remains the durable full history. Nothing is persisted through the controller, and no harness journal or captured-event contract is changed.

Receipts hand off when matching journal content is captured **after this submission's observation boundary**, avoiding accidental matching against identical older prompts. Prompt identity uses timeline turn entries; prose identity uses the corresponding timeline observation sequence, not `Prose.sequence` (which is a presentation step). Sequence replay never displays live receipts as historical evidence. Existing workspace consent, idle-client acknowledgement and exact one-time approvals remain mandatory.

Settings offers **Full available detail** (default), **Collapsed**, or **Hide** exposed reasoning. It changes local presentation only, persists locally, and applies to recorded and native-preview reasoning. It does not change model effort, billing, hidden reasoning availability or native configuration. Ordinary assistant commentary remains ordinary output.

Sources verified 8 October: [Claude programmatic streaming](https://code.claude.com/docs/en/headless), [Claude CLI flags](https://code.claude.com/docs/en/cli-reference), [Codex app-server](https://learn.chatgpt.com/docs/app-server). Documentation describes capabilities; actual exposed thinking varies by native version/model/settings. The implemented Codex connector resumes a **local Codex session**, including a CLI authenticated with ChatGPT; it does not scrape or control arbitrary ChatGPT web conversations.

## Depth graph

The integrated map has an optional **Depth map**, with a separate **Slow background orbit** setting. Both are initially off and persist locally. This is real perspective projection of layout coordinates into the existing Canvas 2D renderer, not a new WebGL/Three.js dependency or an inferred execution graph. Shallow z coordinates are deterministic visual layout, not architecture/dependency strength. Existing spatial-density groups, white dots and evidence-backed import edges remain.

Canvas shapes, DOM labels, hit tests, search/group/file camera destinations and file-arrival anchors use the same projection. Text remains DOM. The orbit redraws at most 15 times per second and advances slowly (roughly a three-minute revolution); it freezes during exploration, hover, selected/expanded reading, search/settings, hidden tabs, reduced motion and low-resource mode. Above 1,500 displayed nodes it stops rather than spinning an unbounded working set. Existing edge budgets and DPR ceiling remain. Low-resource mode also flattens the depth projection. Static/default mode has no ongoing rotation loop.

The explicit builder request is a narrow exception to the earlier no-decorative-loop doctrine: optional background orbit only. There are no idle pulses or fake agent-work animations. Initial delivery freezes the current orientation for exploration and retains the ordinary pan/zoom controls; free three-axis drag, optimized GPU drawing and geometry-aware 3D grouping are future candidates if user testing establishes value. Do not claim this is a force-directed 3D code indexer or that large repositories/physical GPUs are newly certified.

## End-to-end product backlog — retain for both builders

1. **Attachments:** actual file/folder picker, selected-root consent and path checks, clear remove/preview/size limits, native per-harness attachment capabilities. Do not expose a working-looking picker until the corresponding native protocol is implemented. Folder references are not uploads of whole private repositories. Verify protected files/redaction and mixed text/files on Windows/macOS/Linux.
2. **Native settings and permissions:** read effective resumed-session model/effort/approval/sandbox settings through supported protocols; show the actual effective values, then add explicitly submitted, validated per-turn settings changes where supported. Native policy and organization restrictions win. “Full access” must never be a cosmetic toggle or an unannounced fallback, and observer code must remain independent. Current connector still uses conservative Ask permission settings; it does not claim policy synchronization.
3. **Session ownership and synchronization:** active-client conflicts, switching sessions during handshake, reconnect after native exit, auth expiry, duplicate submits, background/subagent completion, late journal writes, and approval races. Validate current native Claude/Codex releases with opt-in real sessions; synthetic protocol tests do not certify every installed version.
4. **Live presentation:** compare captured native block availability against real thinking/text timing; retain truthful waiting states when thinking is omitted. If safe incremental text is later added, its chunk-boundary redaction needs its own acceptance before fragments can be published. Do not reintroduce simulated typing.
5. **Multiple agents:** genuine harness-spawned identities, child tool/prose ownership, narrow readable child surfaces and main-history relationship navigation. No made-up agent names or parallelism.
6. **Depth map validation:** large real repositories, hidden-tab/low-resource battery behavior, CPU/GPU/frame/total-RAM measurements, map search/click accuracy at difficult orientations, shared arrival origins, human readability preference. Keep flat mode available; optional visual depth must not displace reliable reading.
7. **Release:** packaged first-run native discovery/login errors, platform/resource acceptance, manual GitHub CI just before publication, no telemetry, privacy-reviewed exports and the comprehension/preference pilot. Existing backend gates remain distinct from full public-product certification.
