# Decisions log

Every standing product and engineering decision made during Drishya's private development, with the reason it was made. It exists so that nobody re-argues a settled question. Read it before changing capture, privacy, the event schema, the UI's direction or the release process; if you need to change a decision, open an issue that names the entry and the new evidence, and add a new entry that supersedes the old one rather than editing it.

The short version, for a first read, is [Contributor decisions](README.md). The task entries behind many of these are in the [Product Work History](../PRODUCT_WORK_HISTORY.md).

Notes on reading it:

- Entries are the maintainers' own words from the private repository, kept as written after a privacy pass (paths, accounts and recording identifiers removed). Names of tools and tasks (`SEC-3`, `UI-46`) are task IDs in the Product Work History.
- "Builder" means one of the two original maintainers; "Fable", "Opus" and "Sonnet" name the coding agents that worked with them.
- Pull request and issue numbers (#394) refer to the private development repository, kept as an archive; they are not links here.
- Words such as `STATUS`, `TASKS` and "claim" refer to the private tracking files that this public repository does not carry.
- Newest entries come first in the first part; the dated table afterwards is the older, append-only log from September and October 2026.
- Two questions were open when the history was archived: the **trademark** clearance for the name "Drishya" (software classes 9 and 42; the [trademark note](../../TRADEMARKS.md) states what is and is not licensed meanwhile), and **two-factor authentication** for the GitHub organisation.

## Decisions, newest first

- **17 Nov, FEEDBACK-1, how users give feedback (orchestrator's choice for launch; the builders may override):** feedback goes through GitHub issues. The issue forms in `.github/ISSUE_TEMPLATE/` are the channel (bug, idea, harness integration), and every link points at `https://github.com/drishya-dev/drishya/issues/new/choose`. The app carries one quiet text link, "Feedback ↗" in the Home footer and "Send feedback" in Settings under Privacy; it opens that page in a new tab with no referrer and the app sends nothing, because there is no telemetry and no in-app form or analytics to add. GitHub Discussions is off, and turning it on is a repository setting for Yash, so the link is only a commented contact entry in `config.yml` until then. The bug form asks for the Drishya version and no longer requires a verification note from a reporter; the idea form no longer requires one either. The README has a one-line Feedback pointer; the website adds the same link in its own pass. Asking early users for Product Hunt or Show HN reviews belongs to the launch posts, not to the README or the app. Checked by `tests/browser/feedback-link.spec.ts` at 600 and 1440 px.

- **15 Nov, SEC-3, decided (Fable for the builders, Yash delegated; each with the condition checked):** (1) every `git` call goes through a default-deny `readGit` (object-only subcommands, filter drivers overridden, `--ignore-submodules=dirty`), because a repository's own configuration made `git status` run programs; (2) privacy policy `p5`, a string that parses as JSON is redacted inside, and existing stores re-scrub on open, because Antigravity records tool arguments as JSON text and older stores may already hold leaked values; **measured: 4.5 s once at daemon start for 102,415 observations (699 MB of real journals, 264 MB store), 0.0 s afterwards, below one large-session projection rebuild, so no background mode**; (3) image responses are `no-store`, consistent with SEC-3 item 9; **checked: no flash and no extra request on remount in Chromium, so no in-memory image cache**; (4) images are limited to 64 megapixels as well as 4 MiB, for every harness, and the page now says the real reason with the stated size (`apps/ui/src/lib/omitted-image.ts`); (5) at most 64 change streams; (6) the cookie port scope is accepted for release 1 and tracked as SEC-6. Reasons and tests: [threat model](../review/sec-3-threat-model.md).
- **14 Nov, EMBED-1, Yash reports both builders agree:** Release 1 embeds Drishya as a top-level desktop guest, never an iframe; preserve CSP framing denial, Strict cookies, loopback and the request gate. - **11 Nov, Yash: Drishya is open source, with no paid tier for now.** A paid team service may come later, after the main product is stable; word of mouth and open-source contribution come first.
