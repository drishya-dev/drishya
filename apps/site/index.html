Free and open source · Apache-2.0 · Node 24 or later

Why a replay of agent work

You give an agent a task and look away. It reads forty files, runs the tests, sees one fail and edits three of them. Then it writes a summary. The work that led there scrolled past in a terminal, or never showed at all.

Drishya keeps that work and shows it to you while it happens, so you understand the change and the codebase, not only the summary.

How Drishya shows an agent session

  1. Claude Code · CLI

    In the CLI, each action is one line

    The source it read, the failing output and the diff scroll past and are gone.

  2. Desktop app

    In the app, the tools fold into a list

    A chat with the answer. What the agent read and ran sits in collapsed rows you open one at a time.

  3. Drishya

    In Drishya, you see the work itself

    The same session. Each action arrives in order with its real output, on a map of your repository.

  4. Drishya

    Sub-agents keep their own work

    The Explore sub-agent's reads stay with that agent, so you can tell who did what.

  5. Drishya

    The failing test, then the fix

    The test output in full, the edit that answered it, and the run that passed.

  6. Drishya

    And the answer, beneath the work

    The agent's own words, under the work that led to them. Scroll back to replay any step.

  1. Files

    Your files beside the agent's work

    The explorer stays open next to the session. Every file the agent touched is marked where it lives in your repository.

  2. Explorer

    Each file, with every action on it

    Open a file and see each read, search and edit on it in order. Step to an earlier change and see exactly what it was.

  3. Workspace

    The current code, in a real editor

    Read and edit the file as it is now, with your tree and tabs, a step away from the agent's work.

  4. Changes

    A branch or pull request against its base

    Changes shows what differs, files changed on both sides first, and under each file the agent that edited it.

  5. Git graph

    Branches and commits, with the agent's work

    Every branch, the commits on it, and which one holds the session's fix, read-only.

  6. Toolbox

    Step through every use of one tool

    The Toolbox counts each tool and MCP server. Pick one and step through every time it was used, with the rest of the session dimmed.

  7. Prompts

    Every prompt, one move away

    The prompt rail keeps each prompt you sent. Hover one to see what it asked and what the agent did for it, then jump there.

  8. Composer

    Prompt the agent from Drishya

    Send the next prompt to the same session without leaving the work. Opt-in, per repository, and only what you submit.

Run it with one command

npx drishya downloads and runs Drishya without installing it. To keep it, install it once with npm install -g drishya, then run drishya. It opens in your browser and finds the Claude Code and Codex sessions already on this machine.

  1. Run it. Needs Node 24 or later. Nothing to sign up for.
  2. Pick a session. Running sessions show as live; finished ones replay.
  3. Read the work. Open any file, output or diff the agent touched.
Terminal
# run once, without installing
$ npx drishya

# or install it, then run it any time
$ npm install -g drishya
$ drishya

Local, private, no telemetry

Reads, never writes

Agent session files are opened read-only and copied into Drishya's own store on your disk.

Secrets removed first

Keys and tokens are redacted before anything is saved, searched or shown.

No telemetry at all

Drishya sends nothing anywhere. There is no account, no cloud and nothing to opt out of.

You decide when it acts

Prompting an agent from Drishya is opt-in, per repository, and only sends what you submit.

Free and open source

Apache-2.0. Built in the open for developers who work with coding agents. Works with Claude Code and Codex today.
