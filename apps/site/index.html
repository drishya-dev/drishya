Why a replay of agent work

You give an agent a task and look away. It reads forty files, runs the tests, sees one fail and edits three of them. Then it writes a summary. The work that led there scrolled past in a terminal, or never showed at all.

Drishya keeps that work and shows it to you while it happens, so you understand the change and the codebase, not only the summary.

    Tools for working in the codebase

    Everything the agent did, beside the tools you need to act on it. Also included: Changes for branches and pull requests, the Git graph, search across sessions, and a composer to prompt the agent from Drishya.

    Install in one command

    Drishya opens in your browser at a local address and finds the Claude Code and Codex sessions already on this machine. Nothing to sign up for.

    1. Run it. Needs Node 24 or later.
    2. Pick a session. Running sessions show as live; finished ones replay.
    3. Read the work. Open any file, output or diff the agent touched.
    Terminal
    # run in any folder; Drishya opens in your browser
$ npx drishya

    Local, private, no telemetry

    Reads, never writes

    Agent session files are opened read-only and copied into Drishya's own store on your disk.

    Secrets removed first

    Keys and tokens are redacted before anything is saved, searched or shown.

    No telemetry at all

    Drishya sends nothing anywhere. There is no account, no cloud and nothing to opt out of.

    You decide when it acts

    Prompting an agent from Drishya is opt-in, per repository, and only sends what you submit.

    Free and open source

    Apache-2.0. Built in the open for developers who work with coding agents. Works with Claude Code and Codex today.
