Why a replay of agent work

You give an agent a task and look away. It reads forty files, runs the tests, sees one fail and edits three of them. Then it writes a summary. The work that led there scrolled past in a terminal, or never showed at all.

Drishya keeps that work and shows it to you while it happens, so you understand the change and the codebase, not only the summary.

How Drishya shows an agent session

  1. Claude Code · CLI

    In the CLI, each action is one line

    The source it read, the failing output and the diff scroll past and are gone.

  2. Desktop app

    In the app, the tools fold into a list

    A chat with the answer. What the agent read and ran sits in collapsed rows you open one at a time.

  3. Drishya

    In Drishya, you see the work itself

    The same session. Each action arrives in order with its real output, on a map of your repository.

  4. Drishya

    Sub-agents keep their own work

    The Explore sub-agent's reads stay with that agent, so you can tell who did what.

  5. Drishya

    The failing test, then the fix

    The test output in full, the edit that answered it, and the run that passed.

  6. Drishya

    And the answer, beneath the work

    The agent's own words, under the work that led to them. Scroll back to replay any step.

  1. Files

    Your files beside the agent's work

    Open files from your tree into a reader beside the session, one tab each, while the agent's work stays in view. Files the agent added or edited are marked.

  2. File history

    Every action on a file, and each earlier edit

    Every read and edit the agent made to a file. Choose an earlier edit to read exactly that change, and the test runs that followed it.

  3. Workspace

    The current code, in a real editor

    Open any file in Workspace with your tree and tabs, and edit it a step away from the agent's work.

  4. Changes

    This session, a branch, or a pull request

    What this session changed, any branch against main, or an open pull request, each chosen from a list. Every file names the agent that edited it.

  5. Git graph

    Every branch, and where the agents' work landed

    Every local branch and commit as a graph, read-only, beside the session. Choose one branch to read only its own commits.

  6. Toolbox

    Step through every use of one tool

    Pick a tool and step through each time it was used. The rest of the session dims around it.

  7. Prompts

    Every prompt, and what it led to

    The prompt rail keeps each prompt. Hover one to see what it asked, how many actions followed and what failed, then jump there.

  8. Composer

    Prompt the agent from Drishya

    Send the next prompt to the same session without leaving the work. Opt-in, per repository, and only what you submit.

Working with an agent, with and without Drishya

Drishya does not replace your agent. It reads the session the agent already records and shows it in full.

Without DrishyaWith Drishya
Files the agent readA one-line note in the CLI or appThe exact lines it saw
Test and command outputCollapsed or scrolled awayThe full output, kept
EditsA count of lines changedThe diff as written, before later edits
Where the work happenedPaths in text, a separate editor to lookMarked in your file tree and on the map
Branches and pull requestsA separate Git client, no link to the agentChanges and the Git graph, with the agent behind each file
Sub-agents and MCP toolsMixed into one streamEach kept with its own work and counted
LaterScroll back through the chat, if it is still thereReplay any session, live or finished

Local, private, no telemetry

        

          
Reads, never writes
Agent session files are opened read-only and copied into Drishya's own store on your disk.

          
Secrets removed first
Keys and tokens are redacted before anything is saved, searched or shown.

          
No telemetry at all
Drishya sends nothing anywhere. There is no account, no cloud and nothing to opt out of.

          
You decide when it acts
Prompting an agent from Drishya is opt-in, per repository, and only sends what you submit.
